    <div class="rounded-r-lg border-l-4 border-indigo-500 bg-indigo-50 p-6 dark:bg-indigo-950/40">
      <h2 class="mb-3 text-2xl font-bold text-indigo-900 dark:text-indigo-200">Overview</h2>
      <p class="text-indigo-900/80 dark:text-indigo-200/80">
        We built <a href="https://www.npmjs.com/package/nexora-iot-ui" class="font-semibold underline">nexora-iot-ui</a>, a library of React components for IoT and industrial dashboards with an optional data layer that wires them to a real device over Portal — <strong>no backend of your own</strong>. Telemetry and commands travel over a single realtime channel: the board publishes readings, the browser reads the same channel, and commands travel back the same way.
      </p>
    </div>

    <p class="leading-relaxed text-slate-600 dark:text-slate-400">
      The library is validated against real hardware: an ESP32 with a DHT11 sensor publishing temperature and humidity every 2 seconds, and a 28BYJ-48 stepper motor the panel can start and stop. The buttons read the device's state — not the click — and the panel marks data as stale when the board stops responding, because an open socket doesn't mean the hardware is alive.
    </p>
  </section>

  <section class="space-y-6">
    <h2 class="text-2xl font-bold text-slate-900 dark:text-slate-100">The most interesting challenge</h2>
    <p class="leading-relaxed text-slate-600 dark:text-slate-400">
      We discovered that Portal's official React SDK <strong>discards inbound ephemeral messages</strong> — exactly the channel telemetry travels on. We verified it against the live API and decided to implement Portal's wire protocol directly, isolating that layer in a single file so it can be swapped out once the SDK supports it. We preferred 400 lines of our own over a panel that pretends to be live.
    </p>
