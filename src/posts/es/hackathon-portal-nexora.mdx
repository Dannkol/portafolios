    <div class="rounded-r-lg border-l-4 border-indigo-500 bg-indigo-50 p-6 dark:bg-indigo-950">
      <h2 class="mb-3 text-2xl font-bold text-indigo-900 dark:text-indigo-200">Overview</h2>
      <p class="text-indigo-900/80 dark:text-indigo-200/80">
        Construimos <a href="https://www.npmjs.com/package/nexora-iot-ui" class="font-semibold underline">nexora-iot-ui</a>, una librería de componentes React para paneles de IoT e industriales con una capa de datos opcional que los conecta a un dispositivo real por Portal — <strong>sin backend propio</strong>. Telemetría y comandos viajan por un único canal en tiempo real: la placa publica lecturas, el navegador las lee del mismo canal y los comandos regresan por la misma vía.
      </p>
    </div>

    <p class="leading-relaxed text-slate-600 dark:text-slate-400">
      La librería se valida contra hardware real: un ESP32 con un sensor DHT11 publicando temperatura y humedad cada 2 segundos, y un motor paso a paso 28BYJ-48 que el panel puede arrancar y detener. Los botones leen el estado del dispositivo —no del click— y el panel marca los datos como obsoletos si la placa deja de responder, porque un socket abierto no significa que el hardware esté vivo.
    </p>
  </section>

      Descubrimos que el SDK oficial de Portal para React <strong>descarta los mensajes efímeros entrantes</strong> — justo el canal por el que viaja la telemetría. Lo verificamos contra la API en vivo y decidimos implementar el protocolo de red de Portal directamente, dejando esa capa aislada en un solo archivo para poder reemplazarla cuando el SDK lo soporte. Preferimos 400 líneas propias a un panel que finge estar en vivo.
